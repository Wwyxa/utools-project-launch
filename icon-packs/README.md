# Icon packs

Each directory containing a `source.json` is an independently buildable icon pack.

- `source.json` is the maintained source of pack metadata and compact mapping rules. Do not list assets or generated mapping tables in it.
- `icons/` contains the SVG assets. Asset IDs are generated from file names.
- `LICENSES/` contains the source and asset notices included in the release.
- `manifest.json` and `icon-pack-release/` are generated by `npm run icon-pack:build`; do not edit them by hand.

## Updating an icon pack

For an upstream refresh, copy the desired SVG files into the pack's `icons/` directory. Files with the same name are replaced; pack-specific icons with distinct names remain in place. The build does not read or execute anything under `references/`.

Update `source.json` when upstream metadata, the pack version, licenses, or icon mappings change. Rules group all names that use the same icon. `fileNames`, `fileSuffixes`, and `folderNames` may be combined in one rule:

```json
{
  "icon": "folder_type_trellis.svg",
  "folderNames": [".trellis"]
}
```

The generator derives `folder_type_trellis_opened.svg` for the expanded state. It scans `icons/` to generate the asset table, then expands all rules into the runtime mappings in `manifest.json`.

Build and validate all packs with:

```bash
npm run icon-pack:build
npm run icon-pack:validate
```

Set `ICON_PACK_VERSION` to override the release version without editing `source.json`.
