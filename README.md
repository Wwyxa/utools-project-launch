<h1 align="center">开发工作台</h1>

<p align="center">uTools Project Launch · 把本地项目与常用开发任务收进一个入口</p>

本地开发工作台，支持项目启动与管理、脚本配置与日志查看、Git 操作、AI 分析（支持自定义模式）、自动任务、文件浏览、备忘待办和开发环境检测。

## 它能做什么

| 能力       | 说明                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 项目管理   | 搜索、分组、排序和快速打开本地项目，支持配置导入导出                    |
| 脚本与日志 | 配置或自动发现启动脚本，实时查看输出、发送输入和停止进程                |
| 自动任务   | 定时串行执行脚本，支持随机时间窗口、自动输入、超时和执行历史            |
| Git 工作区 | 查看 Diff 和提交图，完成暂存、提交、分支、标签、远端及 stash 等常用操作；提交头像可选接入 GitHub 凭证（自动发现 gh 登录或在设置页粘贴 PAT），提升额度并支持私有仓库 |
| AI 分析    | 总结或评估 Git 变更、生成提交信息，并在已有结果上继续修订               |
| 文件与备忘 | 浏览、预览和轻量编辑项目文件，记录 Markdown 备忘与待办                  |
| 开发环境   | 检测 Node.js、Python、Go、Git、Docker 等工具，也可添加自定义检测项      |
| 外部工具   | 使用偏好的应用或终端打开项目，并提供 Agent 可调用工具，AI 自动完成配置  |

## 开始使用

1. 打开“开发工作台”，添加项目目录并选择项目类型。
2. 手动添加启动脚本，或从 `package.json`、`Makefile` 自动发现可用命令。
3. 从首页运行脚本、打开项目，或进入项目详情使用 Git、文件、备忘和自动任务等工具。
4. 在 uTools 顶部搜索框中按项目名称、路径或类型筛选首页项目；首页不再显示单独的搜索按钮。

在 uTools 中可通过 `开发工作台`、`工作台`、`Dev Workbench` 或 `PM` 唤起插件。

## 可选功能

### 项目启动服务

默认情况下，脚本和自动任务由插件运行。需要在结束插件进程或退出 uTools 后继续运行开发服务、构建脚本或定时任务时，可以在设置页安装并启用 **Project Launch Service**。运行日志、操作记录和自动任务历史使用公共本地存储，不需要启用服务。

- 服务默认关闭，不会自行下载、安装或启动。
- 启用后，新的脚本进程和自动任务由本机服务管理；已有前台进程需先停止。两种执行方式使用相同的日志格式、保留策略和历史查询。
- 开启任务通知后，新版服务统一使用 `beeep` 发送系统通知，标题为“开发工作台”，不依赖插件界面保持打开或处于前台。Linux、macOS、Windows 的具体通知机制及系统限制遵循该库的平台实现。通知权限、免打扰设置和桌面通知组件会影响展示及历史保留，发送失败会写入服务诊断记录。底层接口不可强制取消，服务超时后停止等待；调用未返回期间不继续启动发送，避免后台工作堆积。
- Windows 服务按整个 Job 进程组维护脚本状态，启动器退出后仍有子进程运行时保持运行中；停止操作结束整组进程。Job 由当前服务直接持有，不启动额外的保管进程；关闭服务前仍需停止所有运行中的脚本。退出码代表根启动器，无法汇总所有子进程的退出码。
- 新版服务通过最长 25 秒的等待变化请求同步状态，空闲时不重复传输完整快照；断连后按 1 至 30 秒退避重连，回到前台时立即刷新。关闭服务模式后停止后台同步；旧版服务保留原有同步与插件通知方式，更新服务后启用新版行为。
- 服务仅在本机运行，不需要管理员权限，也不会注册为开机自启的系统服务；设备重启后会停止。
- 安装、更新、验证和日志保留策略均可在设置页管理；自动下载失败时，可从 [GitHub Releases](https://github.com/Wwyxa/utools-project-launch/releases) 手动安装对应平台的文件。
- 禁用或移除服务前，应先停止它管理的活动进程和任务。

服务文件和执行状态位于 uTools v8 插件本地数据目录的 `service/`；运行日志、操作记录、诊断记录及保留策略统一位于 `runtime/`，服务停止后仍可查看。初始存储迁移会将旧运行日志和诊断日志直接迁入统一运行目录，保留旧日志策略（不覆盖已有策略），校验成功后才标记完成，原始文件仍保留。数据工具通过“运行日志与操作记录”管理已完成记录，保留活动运行和直接运行的自动任务认领状态；删除服务目录不会删除统一日志和保留策略。服务协议版本为 3；服务启用但文件缺失或不兼容时，插件会阻止新的运行请求并提示修复，不会静默切回插件执行，以免产生重复任务。

### 文件图标包

设置页可按需安装 `vscode-icons` 衍生图标包，用于项目文件树和 Git 文件列表。图标包独立下载，默认不安装、不联网，也不进入主插件构建产物；安装时会校验下载来源、SHA-256、资源清单和许可证通知，随时可以切回内置图标。

## 数据与权限

- 公共项目配置由 uTools 同步数据库保存；私有项目、插件配置和公共项目的本机环境变量保存在 uTools v8 插件本地数据目录。浏览器预览使用独立的浏览器存储。
- 插件需要本地 Node.js 能力来访问项目目录、运行命令、读取文件、执行 Git 操作和检测开发工具。
- Git 写操作会直接作用于本地工作区，执行暂存、丢弃、提交或切换分支前请确认当前状态。
- AI 分析会将选中的 Git 信息或 Diff 发送给你配置的模型提供方，请按项目的数据策略选择接口。
- 可选项目启动服务使用本地回环连接，自动任务配置会在本机加密保存，不会把项目数据迁移到云端。

### 备份与换机恢复

在设置页的 **数据工具 → 备份与恢复** 中，可以导出本地备份文件，或将备份保存到 uTools 数据库。开启 uTools 数据同步后，数据库备份由 uTools 自动同步；未开启同步时，这些备份仍仅保存在本机。

- 每份备份包含全部公共和私有项目、项目环境变量与本机覆盖、备忘录、待办、自动任务定义，以及插件配置和工作区偏好。不包含项目源码、Git 仓库、运行日志、缓存、服务程序或图标包文件。
- 来源信息只在创建备份时读取计算机名、操作系统和架构，随备份保存；不生成或保存设备身份。
- 备份只做压缩，不加密，可能包含 AI 密钥和环境变量中的敏感值；请妥善管理本地备份文件和 uTools 同步数据。
- uTools 备份列表支持导入、导出为本地文件和删除；删除会同步到其他设备。每份备份通过 `utools.db.postAttachment()` 保存为一个附件，文件超过 10 MB 时提示改用本地导出，不进行分片。保存失败的记录标记为未完成，可以删除后重试。
- 本地与 uTools 备份均使用 `.plbackup` 格式。导入先预览来源、时间和项目数量，再按 **所有项目**、**插件配置** 两类选择；不提供逐项目选择。
- 项目可以合并（同 ID 项目使用备份内容）或整体替换，公共项目的恢复或删除会影响同步数据。换机时可统一替换项目路径前缀，终端和外部应用路径需按新设备核对。
- 恢复前需停止脚本和项目启动服务。导入的自动任务默认暂停，恢复配置时服务默认关闭，确认新机器的环境后再启用。
- 导入前在插件本地数据目录的 `backups/` 下保存一份恢复前备份。导入部分失败时会通过公共浮层提示，可通过本地导入恢复；这不是跨数据库与文件系统的事务回滚。

备份解压后的数据上限为 64 MB。旧的项目配置 JSON 导入导出入口仍保留，它不包含完整插件配置。

## 从源码运行

需要 Node.js 和 npm；只有开发可选项目启动服务时才需要 Go 1.23。

```bash
npm install
npm run dev
```

开发服务默认运行在 `http://localhost:3421`。

构建并加载到 uTools：

```bash
npm test
npm run lint
npm run build
```

构建产物位于 `dist/`。在 uTools 开发者工具中选择 `dist/plugin.json`，不要直接加载项目根目录。

常用命令：

| 命令                                   | 用途                       |
| -------------------------------------- | -------------------------- |
| `npm run dev`                          | 启动 Vite 开发服务         |
| `npm test`                             | 运行 Vitest 测试           |
| `npm run lint`                         | 执行 TypeScript 类型检查   |
| `npm run build`                        | 构建插件到 `dist/`         |
| `npm run go:test` / `npm run go:build` | 测试或构建可选项目启动服务 |

更多模块级校验和基准命令可在 `package.json` 的 `scripts` 中查看。

## 技术栈

Vue 3、TypeScript、Vite、Pinia、Tailwind CSS、Vitest，以及可选的 Go 项目启动服务。

## 版本历程

- **v1.9.0**：加入可独立安装的文件图标包和 uTools AI Agent 项目管理工具；优化 Git 批量操作、日志搜索、确认交互与下载进度。
- **v1.8.x**：增强 Git 文件树、stash 与标签操作，支持项目默认标签页；改善卡片排序、服务稳定性和 Windows 脚本输出兼容性。
- **v1.7.x**：发布可选项目启动服务，加入服务安装更新、持久化日志和运行恢复；扩展自动任务与 Git 远端操作。
- **v1.6.x**：完善自动任务、外部应用、AI 多轮修订、主题联动和开发环境检测。
- **v1.5.x**：形成项目管理、脚本日志、Git 工作区、备忘待办等基础能力。
