# 统一 UI 偏好与拖拽提示状态

## Goal

将项目详情页 Tab 顺序和功能引导状态整合为一份结构化、可版本化的 UI 偏好配置。用户一旦通过有效长按进入 Tab 拖拽模式，关闭并重新打开插件后不再重复显示拖拽提示，同时避免详情页反复访问持久化存储。

## Background

- 当前 Tab 顺序通过独立的 `project-details-tab-order.v1` 数组持久化，并由 Pinia 在启动时加载。
- 当前拖拽提示只使用组件模块内变量记忆，插件重启后会再次显示。
- 根据排序结果推断用户是否知晓功能不可靠：用户可能进入拖拽模式但没有改变顺序，也可能之后将顺序恢复为默认值。
- 功能引导状态属于 UI 偏好，不应混入项目业务数据或为每条提示创建无结构的独立存储键。

## Requirements

1. 定义带 `schemaVersion` 的统一 UI 偏好结构，至少包含：
   - 项目详情 Tab 顺序。
   - 项目详情 Tab 拖拽提示的已知晓版本。
2. 使用版本号表示功能引导确认状态，而不是根据 Tab 顺序推断，也不使用仅能表达一次状态的临时组件变量。
3. 用户长按达到现有拖拽阈值并正式进入拖拽模式时，立即将当前提示版本标记为已知晓；即使最终没有改变 Tab 顺序，也不再重复展示提示。
4. 普通点击、未达到阈值的短按或因移动容差取消的长按不得标记提示为已知晓。
5. Tab 顺序仅在实际变化时更新；提示确认与顺序变化是两个独立状态。
6. UI 偏好在应用启动/项目加载阶段通过 ProjectBridge 读取一次并放入 Pinia；项目详情页不得直接读取 `localStorage`、`dbStorage` 或 preload。
7. 浏览器预览使用 `localStorage`，uTools 宿主通过 preload 使用 `dbStorage`；两条路径必须使用相同的逻辑结构和默认值。
8. 兼容现有 `project-details-tab-order.v1` 数组：
   - 新配置不存在时迁移旧顺序。
   - 旧顺序与默认顺序不同，则视为用户已知晓第 1 版拖拽提示。
   - 旧顺序与默认顺序相同，则保留提示，直到用户第一次有效长按。
9. 对缺失、损坏、重复或包含未知 Tab ID 的持久化数据应用安全默认值、去重和补齐，不得阻止应用启动。
10. UI 偏好持久化失败不得阻断 Tab 点击或拖拽；当前渲染会话仍应保持已更新的 Pinia 状态。

## Acceptance Criteria

- [ ] 新安装或没有 UI 偏好数据时，详情页显示低调的“长按拖动排序”提示。
- [ ] 长按达到拖拽阈值后，即使未换位，提示立即隐藏；返回并打开任意项目时仍保持隐藏。
- [ ] 完全关闭并重新打开插件后，已确认的提示不再出现。
- [ ] 短按或移动超过容差而取消长按后，提示继续显示且确认版本不变。
- [ ] Tab 顺序实际变化后跨项目、跨详情页重建和插件重启保持一致。
- [ ] 只进入拖拽模式但未换位时，不产生无意义的 Tab 顺序写入。
- [ ] 旧的非默认顺序迁移后保持原顺序且不显示提示；旧的默认顺序迁移后仍显示提示。
- [ ] 无效 UI 偏好或旧数据回退到完整默认顺序，应用可继续使用。
- [ ] 每次打开项目详情页不触发新的持久化读取；读取发生在 Store 初始化/加载边界。
- [ ] 浏览器预览与 uTools preload 使用一致的 UI 偏好契约。
- [ ] `npm run lint`、`npm run build` 和 `node --check public/preload.js` 通过。
- [ ] 浏览器手动回归覆盖提示初显、短按、有效长按未换位、有效换位、返回重开和整页刷新。

## Out of Scope

- 通用多步骤新手引导系统、遮罩层或提示动画。
- 设置页中的“重置所有功能提示”入口。
- 将 UI 偏好同步到其他设备或项目导入导出文件。
- 改变现有 350ms 长按阈值、拖拽排序算法或 Tab 键盘切换语义。

## Notes

- 当前提示版本从 `1` 开始；未来交互发生重大变化时可提高版本并再次展示。
