# 完善 Git 提交上下文菜单

## Goal

将提交记录右键菜单扩展为紧凑、分层的 Git 操作入口，使用户能围绕目标提交创建分支或标签、切换提交或关联分支，并安全地管理本地分支。

用户价值：常见的提交定位和引用管理无需离开 Git 提交树，同时危险操作具有一致、明确的确认流程。

## Background

- 当前提交菜单仅支持切换到关联本地分支，或在无本地分支时切换到提交并进入分离 HEAD。
- 当前 renderer/store/preload bridge 已支持本地分支切换和提交 checkout，但尚无创建、重命名、删除分支或创建标签动作。
- 当前快照的 `branches` 仅包含本地分支；提交 `refs` 装饰可能同时包含本地分支、远程分支、标签和 HEAD，需要基于现有 ref 分类逻辑决定展示和可用操作。
- 远程分支装饰代表本地缓存的 remote-tracking ref，不保证与服务器实时状态一致，也不能使用本地分支重命名/删除命令管理。
- Git 支持重命名当前本地分支，但拒绝删除当前 checkout 分支；安全删除 `git branch -d` 会拒绝未合并分支。
- 菜单沿用上一轮已确认的紧凑视觉方向：较小字号、较窄宽度、单行菜单项、视口边缘定位。

## Requirements

### R1. 菜单信息架构

- 菜单顶部展示“新建分支”和“新建标签”，作为第一组操作。
- 第一组之后展示分隔线，再展示切换相关操作。
- 若目标提交不关联可切换分支，只显示切换到该提交并进入分离 HEAD 的操作。
- 若目标提交关联一个或多个分支，逐一展示分支名；每个分支项可展开二级菜单。
- 无论目标提交是否关联分支，都必须保留“分离 HEAD 查看目标提交”的能力；有关联分支时，该动作放入对应分支的二级菜单。

### R2. 分支二级菜单

- 本地分支二级菜单提供切换到分支、分离 HEAD 查看目标提交、重命名和删除；具体可用性必须符合当前分支、工作区状态和 Git 约束。
- 远程分支二级菜单提供“检出为本地 tracking 分支”和“分离 HEAD 查看目标提交”，不得出现本地分支重命名或删除操作。
- 当前分支允许重命名；Git 拒绝删除当前 checkout 分支，因此删除项必须禁用且 bridge 再次校验。
- 删除首先使用 Git 安全删除语义；若仅因分支未合并而失败，可在第二个统一危险确认弹窗中明确提示独有提交风险，用户再次确认后执行强制删除。不得自动升级为强制删除。
- 分支名本身作为可点击徽标；点击后复制完整分支名，不增加额外复制按钮。
- 复制成功必须提供明确但轻量的反馈，悬浮提示应说明点击可复制，并保留完整分支名用于截断场景。

### R3. 创建引用

- “新建分支”以右键目标提交为起点创建本地分支。
- 新建分支弹窗提供紧凑的“创建后切换”复选框，默认不勾选；未勾选时仅创建分支，勾选后创建并切换到新分支。
- “新建标签”以右键目标提交为起点创建标签。
- 新建标签弹窗默认创建轻量标签，并提供紧凑的“附注标签”复选框；勾选后显示必填的标签说明输入框，创建包含 tagger、时间和说明的附注标签。
- 创建流程使用项目现有对话框视觉与交互约定，并校验空值、非法名称和已存在引用。
- Git 名称合法性、引用是否已存在和目标 commit 是否有效必须由 preload/Git 作权威校验，不能依赖已分页的提交装饰。
- 分支和标签沿用 Git 原生的独立 namespace，允许同名；UI 必须用类型图标或徽标消除短名称歧义。

### R4. 风险控制

- 删除分支等高风险操作必须经过项目统一样式的确认弹窗。
- 强制切换导致未提交变更丢失时，继续沿用现有统一确认弹窗。
- 勾选“创建后切换”时若工作区变更会阻止切换，必须进入与普通分支切换相同的确认/错误流程；不得为了完成创建而隐式丢弃变更。
- “分离 HEAD 查看”必须显式要求 detached checkout，即使本地分支恰好指向目标提交，也不得自动切换到该分支。
- 重命名当前分支、删除当前分支、远程引用操作等 Git 限制应在 UI 与 bridge 两侧一致处理，并返回可理解的结果。

### R5. 一致性与兼容性

- 菜单支持鼠标与键盘进入，保持 `menu` / `menuitem` 语义、焦点处理、外部点击与 Escape 关闭行为。
- 主菜单支持方向键/Home/End；分支项支持右方向键进入子菜单，左方向键或 Escape 返回主菜单，关闭后恢复触发点焦点。
- 多分支、长分支名和视口边缘场景下，菜单与子菜单不得溢出或出现双行项目。
- 不新增菜单框架或运行时依赖，优先复用现有浮层定位、图标、语义色、ProjectActionDialog 和 Git bridge/store 模式。
- 提交引用必须使用无歧义的结构化传输或等价机制，不能继续依赖按逗号拆分 `%D`，以免误解析 Git 合法的逗号分支名或标签名。

## Acceptance Criteria

- [ ] 目标提交无关联分支时，切换组只显示“切换（分离 HEAD）”并能执行现有 checkout 流程。
- [ ] 目标提交关联一个或多个分支时，所有分支均显示为单行项并能展开对应二级菜单。
- [ ] 本地分支子菜单包含切换、分离 HEAD 查看、重命名和删除；不可执行的当前分支或 Git 受限操作有明确禁用或提示状态。
- [ ] 远程分支子菜单包含检出为本地 tracking 分支和分离 HEAD 查看，不包含本地重命名或删除。
- [ ] 删除本地分支默认执行安全删除；当前分支不可删除，未合并分支不会被自动强制删除。
- [ ] 安全删除因未合并而失败时，只有经过第二次危险确认才能强制删除；取消确认时分支保持不变。
- [ ] 点击分支名徽标可复制完整名称，悬浮提示说明行为，复制成功后用户能看到反馈。
- [ ] 可从目标提交创建本地分支和标签，成功后刷新快照/提交装饰并显示操作结果。
- [ ] 新建标签默认创建轻量标签；勾选“附注标签”后要求输入说明并创建附注标签，两种标签均指向右键目标提交。
- [ ] 新建分支弹窗默认只创建；用户勾选“创建后切换”后才切换，且切换风险处理与现有分支切换一致。
- [ ] 删除分支和任何可能丢失工作区数据的操作均使用现有统一确认弹窗。
- [ ] 菜单和子菜单在紧凑及视口边缘场景保持单行、可读、可滚动且不越界。
- [ ] 鼠标、ContextMenu/Shift+F10、方向键、Home/End、左右方向键与 Escape 均按主/子菜单层级工作，关闭后焦点可恢复。
- [ ] bridge/store/UI 的新增 Git 操作具备针对成功、名称冲突、当前分支限制和命令失败的自动化验证。
- [ ] 包含逗号等 Git 合法字符的分支/标签装饰不会被错误拆分或分类。

## Out of Scope

- 提交历史改写、合并、变基、重置、推送或拉取流程。
- 远程仓库侧分支重命名协议或删除远程分支。
- 标签 GPG 签名、签名密钥选择及其他高级发布配置。
