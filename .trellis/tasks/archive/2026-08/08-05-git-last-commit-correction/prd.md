# 修正与撤销最近提交

## Goal

让用户可以修订刚创建的 HEAD 提交，或像 VS Code 一样撤销最近提交并继续编辑，同时清楚地区分重写 HEAD 与创建反向提交两种语义。

## Background

- 当前提交区只支持从 staged 变更创建普通提交，没有 amend 模式。
- 当前提交历史支持检出和引用管理，但没有撤销 HEAD 的操作。
- VS Code 的 “Undo Last Commit” 对普通提交执行 soft reset 到 `HEAD~`；对初始提交删除 `HEAD` 并取消暂存；之后把原提交信息恢复到提交输入框。

## Requirements

- R1：提交区提供明确的“修订上次提交”模式，只作用于当前 HEAD，不允许选择任意历史提交。
- R2：进入 amend 模式时使用 HEAD 的完整提交信息填充提交输入；用户可以修改信息，并可把 staged 变更并入 HEAD。
- R3：amend 会重写 HEAD，执行前显示确认；没有 HEAD、仓库状态不可用或没有可提交内容且信息未变化时不执行空操作。
- R4：提供“撤销上次提交”操作，并在确认内容中明确说明它不会创建 revert 提交，而会移除 HEAD 提交并保留文件改动。
- R5：普通 HEAD 提交按 VS Code 语义 soft reset 到第一父提交，使被撤销提交的改动保留在 staged 状态，并把原提交信息恢复到当前仓库的提交草稿。
- R6：初始提交按 VS Code 语义删除 `HEAD`，保留工作区文件并取消暂存，使仓库回到无提交状态，同时恢复原提交信息。
- R7：HEAD 为 merge commit 时必须显示额外风险说明并再次确认按第一父提交撤销。
- R8：amend 和撤销上次提交作用于当前选中的可用仓库上下文；成功后刷新提交、引用、状态和工作区信息。
- R9：两项操作仅在 HEAD 附着于本地分支时可用；detached HEAD 提示用户使用外部 Git 工具处理。

## Acceptance Criteria

- [ ] 用户可以用现有提交输入和 staged 变更修订 HEAD，成功后历史中只出现修订后的提交。
- [ ] amend 前后提交哈希发生变化，工作区和暂存区状态与 Git 结果一致。
- [ ] 撤销普通 HEAD 后，提交历史回到父提交，被撤销改动保持 staged，原提交信息恢复到输入框。
- [ ] 撤销初始提交后仓库没有 HEAD 提交，文件仍存在并处于未暂存状态，原提交信息恢复到输入框。
- [ ] merge HEAD 未经额外确认不会被撤销。
- [ ] detached HEAD 不会执行 amend 或撤销上次提交，也不会创建新的悬空历史。
- [ ] 无 HEAD、操作失败或用户取消时，不改变提交历史、工作区或提交草稿。
- [ ] 操作名称、确认文案和结果反馈不会把“撤销上次提交”描述成 revert。

## Out of Scope

- 修改任意旧提交、交互式 rebase、通用 reset 模式和自动 force push。
- amend 作者、日期、签名、hook 或 `--no-verify` 选项。
