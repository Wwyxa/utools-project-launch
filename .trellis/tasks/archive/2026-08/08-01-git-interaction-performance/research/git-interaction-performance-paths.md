`readGitStatusSnapshot` first discovers the root, then concurrently requests short branch status, symbolic HEAD, short HEAD hash, NUL porcelain status, unstaged numstat, staged numstat, local branches, remotes, and upstream/divergence (`public/preload.js:4537`). This work runs on the preload event loop and scales with untracked file count and bytes, not just changed-path count.

Workspace inventory is independently expensive. It probes repository type, Git directory, object format, and root; enumerates worktrees, `.gitmodules`, local submodule config, and index gitlinks; then runs per-entry status jobs with at most four workers (`public/preload.js:2103`, `public/preload.js:2140`, `public/preload.js:2180`, `public/preload.js:2251`, `public/preload.js:2480`). Each initialized direct submodule can add object-format, superproject, HEAD, symbolic-ref, and status commands. Index-only stage/unstage does not need this inventory to make the changed-file rows correct, although a later/background inventory refresh remains useful for linked-worktree status, staged gitlinks, or `.gitmodules` changes.

### Highest-Value Measurements

1. **Stage/unstage critical-path decomposition**: time write, status refresh, workspace inventory, and optional selected-diff reload separately. Record both wall time and per-category command count. Repeat with 0, 100, and 1,000 small files in one nested untracked directory; also vary one large text file. This discriminates Git process overhead from the synchronous filesystem scan.
2. **Initial-load duplicate requests**: spy on `readGitSnapshot` and `readGitWorkspaceSnapshot` while mounting directly into the Git tab with no snapshot. The parent 15-second refresh and Git-tab forced refresh can race. A duplicate full snapshot is more valuable to remove than micro-optimizing parsing.
3. **Pagination ref enumeration**: measure page append at low and high ref cardinality while commit count stays fixed. Separate `git log` duration from `for-each-ref`/HEAD duration. This tests whether caching structured refs within a ref version is worthwhile.
4. **Tooltip cold/warm/remount matrix**: count file-detail requests, avatar requests, Git children, and HTTP calls for leave-before-450-ms, first open, adjacent-hash switch, same-hash return, and component remount. Measure summary-ready separately from avatar-ready so optional network latency cannot hide local-content performance.
5. **Full snapshot overlap**: record command start/end intervals, not only totals. `readGitSnapshot` deliberately launches status and history concurrently, and status itself launches nine tasks. Excess concurrency may increase wall time on Windows even if individual commands look cheap.

Do not start with DOM profiling or virtualization. The current first page is bounded at 80, while the code already exposes much larger command and synchronous-I/O surfaces. Profile row rendering only if bridge completion is fast but the next rendered frame remains slow.

### Repeatable Fixture And Measurement Method

Reuse the standard-library harness already present: `scripts/validate-git-commits.mjs` creates a temporary repository and evaluates the real preload in a VM (`scripts/validate-git-commits.mjs:12`, `scripts/validate-git-commits.mjs:60`); `scripts/validate-git-workspace.mjs` already builds linked worktrees and direct submodules (`scripts/validate-git-workspace.mjs:13`, `scripts/validate-git-workspace.mjs:350`). No benchmark dependency is needed.

Fixture shape:

- Create under `fs.mkdtempSync(os.tmpdir())`; use `git init -b main`, a fixture-local user name/email, `GIT_CONFIG_NOSYSTEM=1`, a fixture-local global config/home, and fixed author/committer dates.
- Make 90 deterministic commits: enough for an 80-row first page plus one real append page without generating irrelevant history volume.
- Diverge `feature` and `main`, create a real merge commit, one lightweight tag, one annotated tag, and several refs pointing to old commits.
- Configure a synthetic `origin`/upstream ref without network access. For avatar tests use a GitHub-shaped URL and a deterministic sandbox `fetch` stub; never call the network in the benchmark.
- Commit a tracked file, append and stage one change, then append another change to the same file. Add a staged rename and a nested untracked directory. Keep untracked file count and byte size as fixture parameters.
- Use a base inventory profile with no related checkout and one scale profile with two linked worktrees plus one initialized direct submodule. This isolates fixed write/status cost from inventory growth.

Measurement protocol:

- Restore the exact precondition before each sample, then clear recorder data. For stage samples, unstage the target during setup; for unstage samples, stage it during setup. Exclude setup commands from measured counts.
- Time each top-level action with `performance.now()`. Keep the first invocation as process/cache-cold evidence, then report the median of at least five warm runs. Also retain min/max or individual samples so a single antivirus/indexer spike is visible.
- In the VM's custom `require`, proxy `child_process.execFile`, `execFileSync`, `spawn`, and `spawnSync`. For executable `git`, record normalized argv after removing `-C <fixture>`, start/end timestamps, exit status, and a category (`root`, `status`, `numstat`, `history`, `refs`, `workspace`, `detail`, `write`). Callback and `close` wrappers preserve real behavior while measuring it.
- Proxy `fs.readdirSync` and `fs.readFileSync` only for paths below the fixture root. Record directory calls, file calls, and bytes read. This makes untracked expansion visible without changing product code.
- For Store/UI request counts, follow the existing Vitest pattern of installing `window.projectBridge = { ...getProjectBridge(), method: vi.fn(...) }` (`src/lib/projectBridge.workspace.test.ts:139`). Assert exact requests independently from real-preload timing.
- Report per scenario: renderer bridge calls, Git child count by category, filesystem calls/bytes, HTTP calls, bridge wall time, and user-visible completion time. Keep preload timing and rendered-frame timing separate.

“Cold” is necessarily scoped: a fresh VM resets preload caches, but it does not reliably flush operating-system filesystem caches on every supported platform. Label those samples VM/cache-cold rather than claiming disk-cold behavior.

### Cache And Lightweight-Refresh Invalidation Boundaries

| State / candidate reuse               | Safe key and reuse boundary                                                                                                                           | Required invalidation / rejection                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tooltip file details                  | Repository `contextKey` + immutable full commit hash; successful/loading/unavailable state may be reused for the renderer session.                    | Clear on project path/repository target change and explicit user reset; reject late results by context and request generation. Ref changes alone do not alter an existing commit object, but pruning unreachable/unloaded hashes bounds memory. Current code provides generation rejection and context clearing (`src/components/project/GitTab.vue:2605`, `src/components/project/GitTab.vue:3253`) but loses all details on component unmount. |
| Avatar result                         | GitHub owner/repository + full hash, as preload already uses.                                                                                         | Repository URL selection changes naturally produce a new key. Failed/offline `null` is currently cached with no TTL until FIFO eviction or preload restart; it must never block local summary. Remote/upstream discovery still repeats before every preload cache lookup.                                                                                                                                                                        |
| Full snapshot in flight / short reuse | Existing repository `contextKey`; initial detail entry may reuse a snapshot younger than 15 seconds (`src/components/project/ProjectDetails.vue:34`). | Internal index writes use mutation version; internal ref writes use the project-wide ref version; project/path changes clear coordination (`src/store/useStore.ts:227`, `src/store/useStore.ts:2035`). Manual refresh must stay forced. A TTL is only a UI reuse policy, not proof that external refs are unchanged.                                                                                                                             |
| Status refresh                        | Repository `contextKey`; only equivalent in-flight reads are reusable.                                                                                | Every write must produce a fresh Git-derived status. Current loop retries when mutation/ref versions change (`src/store/useStore.ts:2450`). Rename, untracked, partial staging, batch writes, and external changes must not be corrected optimistically.                                                                                                                                                                                         |
| Commit page / structured refs         | Commit page key is context + ref epoch + `skip` + `limit`; ref presentation may be reused only inside the same proven ref epoch.                      | Invalidate on internal ref mutation, repository switch/path change, manual forced refresh, and detected external refresh. Current load-more checks context, internal ref version, token, and current length (`src/store/useStore.ts:2499`), but a manual full refresh or external ref change does not itself bump the internal ref version or cancel a same-length in-flight page. Any ref cache must close this gap.                            |
| Workspace inventory                   | Project path plus inventory generation. It can remain visible while a background refresh runs.                                                        | Refresh after writes that can affect selected/related status, gitlinks, or `.gitmodules`; refresh on project path change, manual refresh, and repository inventory actions/external recovery. It should not gate stage/unstage changed-file correctness. Current forced writes replace the token and ignore older results, but still await the new inventory (`src/store/useStore.ts:2407`, `src/store/useStore.ts:2685`).                       |

External-change behavior is currently manual/time-based, not watcher-based. Detail mount may skip a full read for 15 seconds, manual refresh forces snapshot and inventory, and application focus/visibility recovery only reconciles runtime processes (`src/App.vue:40`); it does not refresh Git. Any longer-lived history/ref cache therefore needs an explicit external-refresh policy, but a filesystem watcher is not justified before measurement.

### Complexity To Defer

- Do not introduce virtual lists, workers, databases, native Git bindings, or third-party cache/benchmark packages before command/I/O measurements identify a remaining bottleneck.
- Do not add filesystem watchers, ref polling, a generalized cache service, or a cross-process invalidation protocol. Manual forced refresh plus existing mutation/ref generations is the minimum baseline; add external detection only when stale-data evidence requires it.
- Do not use optimistic stage/unstage state as the correctness source. A lightweight refresh may remove branch/remote/workspace work, but staged/unstaged rows must still come from fresh Git porcelain/numstat output.
- Do not cache an entire status snapshot across writes or treat a TTL as ref validity. Keep caches narrow: immutable commit details and ref data tied to an explicit repository/ref generation.
- Do not combine Git commands merely to lower a counter if parsing becomes fragile or wall time does not improve. First remove duplicate root/ref/inventory work and synchronous untracked scans shown by the recorder.
- Do not optimize avatar delivery ahead of local summary. Avatar failure/offline behavior is optional; measure summary-ready and avatar-ready separately.
