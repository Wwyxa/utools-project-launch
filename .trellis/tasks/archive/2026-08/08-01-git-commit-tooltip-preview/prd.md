# 重构 Git 工作区布局与提交预览

## Goal

把 Git 页重组为稳定的双栏工作区：左侧集中承载提交输入、工作区更改和提交历史，右侧始终承载文件审阅。左侧采用 VS Code 风格的紧凑折叠区，提交树减少非必要信息，并通过连续 hover preview 和自动分页支持高效浏览。

用户价值：提交、暂存、浏览历史和打开 diff 形成稳定路径；右侧不再在“提交树 / 审阅”之间切换，宽度优先留给代码审阅，左侧则可按当前任务收起不需要的内容。

## Confirmed Facts

- Git 页由 `src/components/project/GitTab.vue` 控制，现有横向 `useResizableSplit` 左侧显示提交输入和工作区更改，右侧通过 `rightContext` 在提交树与审阅之间切换。
- `GitDiffViewer.vue` 自带 diff 滚动、hunk 导航和换行控制，可以脱离右侧模式标题栏独立填满右侧面板。
- 工作区更改已经分为 staged / unstaged 可折叠组，并已有批量暂存、取消暂存和丢弃操作。
- 提交树已有筛选、AI 分析、多选、内联文件展开、列表/树形文件视图、右键菜单、连续 SVG graph 和 hover preview。
- 当前提交行显示独立选择按钮、graph、hash、标题、refs、作者和时间；普通单击展开文件，选择按钮负责 AI 多选。
- 当前分页由底部“加载更多提交”按钮触发；store 每次追加最多 80 条，已有上下文校验、并发去重和 `hasMoreCommits` 状态。
- 当前 hover preview 的在途实现已经具备内容自适应宽高、实际 DOM 尺寸观察、首次延迟、连续切换即时更新和生命周期清理；迁移提交树后需要把水平锚点从左侧改为右侧。
- 普通 DOM 不能绘制到原生应用窗口之外；本布局将提交树放在左侧后，preview 可以在应用窗口内自然覆盖右侧审阅区域。

## Requirements

### R1. 稳定双栏结构

- 保留现有可调横向分隔器和左窄右宽的双栏比例。
- 左侧集中放置“更改”和“提交树”两个一级折叠区；右侧始终为审阅视图。
- 删除右侧“提交树 / 审阅”模式切换、模式标题栏及 `rightContext` 状态，不再因选择文件而切换右侧模式。
- 随右侧模式标题栏删除仅存在于该标题栏的工作区文件“上一个 / 下一个”按钮；文件切换统一从左侧变更列表完成，`GitDiffViewer` 自身的 hunk 导航继续保留。
- 工作区文件和历史提交文件都在右侧同一个 `GitDiffViewer` 中打开；未选择文件时显示紧凑空状态。

### R2. 左侧折叠工作区

- “更改”和“提交树”一级标题行高度统一为约 32px：左侧为折叠箭头、标题和数量，操作按钮统一为约 24px 的纯图标按钮并靠最右侧排列。
- “更改”标题行放置 AI 生成 commit message、全局丢弃全部变更和提交按钮；按钮复用现有禁用、loading、tooltip 和无障碍标签。
- “更改”展开内容包含初始 40px、内容驱动且最高 144px 的 commit message 输入区；输入区在分栏宽度变化后重新测量，超出上限时使用统一滚动条。
- “暂存的更改”和“更改”直接作为“更改”的弱化二级折叠行，不再包在“变更列表”父栏内；暂存/取消暂存操作各自位于所属分组，丢弃全部保留在一级栏。
- “提交树”标题行承载现有选择全部可见、清空选择、筛选、AI 分析和提交文件列表/树形切换按钮；删除回到顶部和回到底部按钮。
- 两个一级区都展开时，“更改”使用受限高度并在内部滚动，提交树获得剩余空间；任一区收起后，另一区使用释放出的空间。
- 折叠只改变布局，不清空 commit message、staged / unstaged、筛选、选择或内联提交文件展开状态。
- 左侧不增加嵌套卡片、独立工具栏或新的拖拽分隔器。

### R3. 精简提交树

- 提交行移除独立选择框和 hash 列，不显示 hash 文本或 hash 复制按钮。
- 提交行不使用卡片边框、圆角外框或 ring；hover、当前 HEAD 和多选状态使用平坦整行背景、文字或轻量侧边强调表达。
- 行内优先保留连续 graph、commit title、必要 refs，以及低对比度的作者和相对时间；完整 hash、绝对时间、message/body 和变更摘要由 hover preview 承载。
- 普通左键保持展开/收起该提交的文件列表；`Ctrl + 左键` 或 macOS `Cmd + 左键`只切换 AI 多选，不同时触发展开。
- 多选结果通过整行选中状态和提交树标题行计数反馈，不恢复复选框。
- 不增加 Shift 范围选择、拖选或新的选择模式。

### R4. 提交 hover preview

- preview 固定出现在左侧提交树的右边，左边缘与左侧面板右边界保持 8px 间距；不实现方向回退或指针跟随。
- preview 宽高由当前提交实际内容决定，最大宽度 384px、最大高度 400px，并进一步受窗口右、上、下各 12px 安全边距约束。
- 默认让 preview 垂直中心对齐当前提交行；触及窗口顶部或底部时只做保持完整可见所需的最小位移。
- preview 在变更摘要同一行的前方显示短 hash；点击该 hash 复制完整 hash。保留作者头像、作者与时间、Markdown message/body、变更摘要、refs、文本选择和内部滚动，但不显示独立复制图标或复制 message 按钮。
- 整个提交行作为 hover trigger，经过 graph、标题、refs 或行内空白时保持同一 hover 会话。
- hover card 完全关闭时，首次进入提交行仍等待 450ms 后打开，避免鼠标扫过列表时频繁弹出。
- hover card 已打开或正处于 180ms 延迟关闭期间时，进入另一提交行必须立即切换提交内容和垂直位置，不再等待 450ms。
- 鼠标从提交行横向移入卡片后，卡片保持打开并允许选择文字、滚动正文和使用复制操作。
- 提交行与卡片都失去悬浮后，延迟 180ms 关闭；在延迟期间重新进入任一提交行或卡片会取消关闭。
- 首次渲染、切换提交和异步详情改变尺寸后，使用实际 DOM 尺寸重新校正位置，不使用固定高度估算。

### R5. 自动加载更多提交

- 删除提交树底部“加载更多提交”按钮，以原生 `IntersectionObserver` 观察提交列表底部哨兵。
- 哨兵进入提交树滚动视口底部预取范围时自动加载一页；复用现有 `handleLoadMore`、`isLoadingMore`、store 并发去重和 80 条分页。
- 自动触发一次只加载一页；筛选导致哨兵持续可见时不主动循环追页到仓库末尾。
- 底部保留固定高度、无按钮文字的轻量哨兵空间，只在请求中显示小型 loading 指示，避免 spinner 出现/消失改变列表高度。
- 新提交只追加到现有列表底部，保持 hash key、当前 `scrollTop`、已加载行 DOM 和 graph 坐标稳定；不使用列表淡入、位移动画或整体 loading 替换。
- 提交树折叠、组件卸载或仓库上下文切换时断开旧 observer；重新展开或切换上下文后观察当前哨兵。

### R6. 生命周期与兼容行为

- 保留现有 Escape、项目或仓库上下文切换、组件卸载时的关闭和异步请求防串线行为。
- 提交树滚动、窗口 resize、折叠提交树或其他外部布局变化时关闭 preview；preview 内部正文滚动不得触发关闭。
- 保留现有仓库选择、Git 写操作、筛选、AI、内联文件展开、context menu、文件审阅滚动恢复和可调分栏行为。
- 不增加运行时依赖、持久化 schema 或 bridge/store 数据协议。

## Acceptance Criteria

- [ ] AC1: Git 页左侧依次显示“更改”和“提交树”折叠区，右侧始终显示审阅或空状态；不存在“提交树 / 审阅”模式标题栏。（R1）
- [ ] AC2: 两个一级标题行高度和图标按钮尺寸统一，按钮全部靠最右侧；更改区提供 AI、全局丢弃和提交，提交树提供选择、筛选、AI 和文件视图操作，但不再提供回到顶部/底部。（R2）
- [ ] AC3: “更改”可整体收起；展开后输入框以 40px 起始高度随内容增长、最高 144px，并会在分栏宽度变化后重测。其下“暂存的更改”和“更改”直接独立折叠、视觉弱于一级栏，批量操作无回归。（R2）
- [ ] AC4: 两个一级区同时展开时各自可滚动且不互相遮挡；收起任一区后另一区使用释放空间，折叠前的输入、筛选、选择和展开状态仍保留。（R2）
- [ ] AC5: 提交行不再显示选择框、hash 或卡片外框，只显示 graph、title、必要 refs 及弱化的作者/相对时间；普通单击展开文件，Ctrl/Cmd 单击只切换多选，选中状态和标题计数清晰。（R3）
- [ ] AC6: 工作区文件和历史提交文件都直接更新右侧 `GitDiffViewer`，不会切换整个右栏；diff 导航、换行和滚动恢复可用。（R1、R6）
- [ ] AC7: preview 始终位于左侧提交树右边约 8px，最大 384px × 400px，并完整落在窗口右、上、下各 12px 内；短内容紧凑，长正文内部滚动。（R4）
- [ ] AC8: preview 的变更摘要前显示可点击短 hash，并复制完整 hash；没有独立复制图标或复制 message 按钮。首次打开约等待 450ms，打开后切换提交立即更新，鼠标可移入选择和滚动，离开约 180ms 后关闭。（R4）
- [ ] AC9: 顶部、中部、底部提交及异步头像/摘要加载后，preview 仍按真实尺寸对齐且不裁切、重叠或明显跳动。（R4）
- [ ] AC10: 提交树底部没有“加载更多提交”按钮；接近底部时自动追加一页并显示稳定的小型 loading 状态，不改变用户当前滚动位置或导致行、graph、滚动条明显颤抖。（R5）
- [ ] AC11: 自动加载不会并发重复请求，也不会因筛选后哨兵持续可见而自动连续加载全部历史；折叠、切换仓库和卸载后无旧 observer 或旧响应串入。（R5、R6）
- [ ] AC12: 正常宽度、最小左栏宽度和实际 uTools 紧凑窗口下，标题、图标、文本、折叠内容、preview 和右侧 diff 均无重叠或不可达控件。（R1、R2、R3、R4）

## Out of Scope

- 不保留右侧提交树模式或“提交树 / 审阅”切换。
- 不把已删除的工作区文件“上一个 / 下一个”按钮迁移到左侧标题行或 diff 浮动工具栏。
- 不为左侧折叠区增加拖拽高度分隔器、嵌套卡片或第三个一级区。
- 不实现 Shift 范围选择、拖选、键盘多选模式或重新加入复选框。
- 不为自动分页增加虚拟列表、滚动恢复框架、手动加载按钮或自动追页到全部历史。
- 不实现 preview 方向回退或左右自动翻转。
- 不创建原生透明窗口、子窗口或跨窗口 hover 交互。
- 不增加点击固定、常驻详情面板或新的提交详情入口。
- 不调整头像来源、提交摘要数据源或 Git 数据协议。
- 不引入第三方浮层、定位或动画依赖。
- 不追求与 VS Code 像素级一致；参考其内容自适应尺寸、面板外侧定位和连续浏览行为。

## Technical Notes

- 优先删除 `rightContext` 及相关模板分支，再重排已有区域；不复制提交树、审阅或 Git action 状态。
- preview 继续复用当前 `Teleport`、fixed 外壳、open/close timers、详情缓存、`ResizeObserver` 和内部滚动区域，只反转水平锚点并增加 hash 展示。
- 自动分页复用现有追加数据流和 loading guard，以原生 `IntersectionObserver` 和固定高度哨兵替代按钮。
- 本次需求在上一版实现后发生实质变化，任务回到 planning；更新 `design.md`、`implement.md` 并重新获得批准后再继续产品代码修改。
